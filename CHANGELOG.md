# Changelog

Activity display now uses stable working/waiting/ready states on both surfaces. Individual tool names no longer rotate through the activity field; duplicate aggregate errors display removed, category failure counts retained.

## Unreleased — B2b: long-history measurements and real-host acceptance (phase 3 B2b)

**Measurement and acceptance round; defaults unchanged.** All B1 measurement-plan items were executed against the real pinned Pi 0.85.1 SDK, and the raw records are committed under `docs/` (`performance-b2b-ledger.json`, `performance-b2b-usage-ab.json`, `host-acceptance-b2b.json`, `pi-stream-ab-b2b.json`). `widget` + `observed` remain the defaults; no gate was relaxed.

- **Measured initialization costs (documented trade-off).** Ledger attach on a real `SessionManager`: ~2–3 ms at 1k entries, ~21–24 ms at 10k, ~199–234 ms at 100k; the largest single pause at 100k (3.3–6.9 ms) is dominated by the SDK's own O(N) `getEntries()` copy (~2.1–2.4 ms), which slicing cannot help. Aggregation slices stay 0.25–0.67 ms against the unchanged 2 ms budget; retained memory after release is ≤ 2.1 MiB, with a zero-work control window bounding V8 heap-accounting noise.
- **Steady state proven cheap.** Adding 1/32/2048 records per turn reconciles in 0.065–0.46 ms of ledger-internal work with zero new `getEntries()` calls (asserted), tracking the added count rather than history size; over-cap appends recover through exactly one rebuild; mid-slice catch-up and session-switch cancellation (16–30 µs sync) were exercised at every size.
- **Real-host acceptance (9/9 scenarios).** With a deterministic in-process fixture provider (zero network/credentials/billing) in the real TUI: 10k-entry branched resume, a live read-tool turn, two live compactions sharing one summary text over an all-same-summary history (the SDK's `find(summary)` hazard live), `/tree` branch navigation plus back-to-root leaf reset and re-append, model switch, `/new` during a 100k-entry baseline, dual-footer coexistence in both `-e` load orders, and a post-HUD async `message_end` replacer — every checkpoint's ledger totals equal an independent file-oracle reduction.
- **Live streaming/tool/keyboard A/B (20 trials).** Warm inter-token cadence within ±1.4%, keyboard echo and tool turns within noise, tool completion in all trials; the HUD's measured per-turn terminal cost is one ~455-byte coalesced footer repaint ~150 ms after completion (`maxFlushMs` single-digit).
- **Fixes found by the measurements.** `accumulateUsage` no longer allocates per record (a 100k-entry rebuild used to generate ~24 MiB of tuple garbage, inflating GC pauses); `/hud status` diagnostics now publish the ledger's totals as bounded scalars so real-host verification can compare against an independent oracle.
- **Still open, honestly.** Human dark/light terminal visual acceptance, the cross-platform matrix and the default-footer evaluation (not taken). No paid provider was contacted; no release or push was made.

## Unreleased — optional full-session usage ledger (phase 3 B2a)

**Opt-in, not the default.** `usageScope: observed | session` (default `observed`) plus `/hud scope observed|session` select which numbers the usage fields show. The scope is independent of `surface`, which stays `widget` by default. `session` displays full-session totals labelled `sess*` (Chinese `全会话*`); the observed counters, `ctx(last)`, `CH` and tool categories keep their since-attach/reset scope in both modes.

- **Ledger, not counters.** A dedicated module (`src/usage.ts`) aggregates the current SessionManager's entries — all branches, pre-compaction messages, error/aborted responses and summary records — under the built-in footer's four record categories: assistant, tool results carrying usage, compaction and branch summaries. The four token fields and `cost.total` stay separate; cached tokens are never folded into input.
- **Bounded acquisition.** One sliced, cancelable baseline per rebuild (512 entries or ~2 ms per slice, whichever comes first) captured with one `getEntries()` call; steady turns reconcile only newly committed records at `turn_end`/`agent_settled` by walking `getEntry(id).parentId` from the leaf back to the committed cursor, so increments and baselines never overlap and duplicate notifications never double count. Tree navigation and compaction rebuild once; a session switch, `/hud off` or leaving `session` cancels all work and releases the O(N) array. Chain anomalies drop the whole uncommitted batch, mark the data partial and schedule exactly one recovery rebuild — never an idle retry loop. `message_end` only marks the snapshot updating, so a later extension replacing the observed message cannot skew the account.
- **Honest missing data.** Missing, negative, NaN or Infinity values mark that field unknown (`+?`) instead of being dropped; an assistant without usage marks the data incomplete; a usage-less tool result is out of scope, never an unknown charge; a usage-less summary keeps the token subtotals and marks the cost incomplete; an explicit zero cost stays a valid zero; all-unknown cost shows `?`; saturated sums show `limited*`. `↻` (ASCII `~`) marks updating, `?` marks loading, and the scope label plus markers sit before the counters so right-edge truncation cannot hide them. A host without the read-only entry surface degrades explicitly to observed-labelled data; `/hud status` reports scope, status, rebuild reasons, host call counts and missing-field counts.
- **Audited boundary.** `getEntries`/`getEntry`/`getLeafId`/`getSessionId` may be called only inside the marked history boundary of `src/usage.ts`, never in render or per-token paths; `getBranch`/`getContextUsage` stay forbidden everywhere. `scripts/check.mjs` enforces this like the footer boundary.

Verification for this phase: 244 tests (`tests/usage.test.mjs` covers the B1 correctness matrix with an independent oracle reducer), `npm run verify` with unchanged gates, `npm run package:check`, the pinned Pi 0.85.1 SDK contract check (now covering the ledger manager/entry/`turn_end` contracts) and a new `scripts/usage-oracle-check.mjs` that runs the ledger against real `SessionManager.inMemory` histories and compares totals with the SDK's own usage-totals module. An external review round fixed three reported issues — a frozen ledger after `resetLeaf()`-style tree navigation to the root (the null cursor is now a legal anchor), a missing recovery rebuild after a failed baseline catch-up (over-cap append bursts now recover), and session cost fields that lost their scope/status marks when rendered without the token field (`sess*`, updating, incompleteness and saturation marks are now carried independently) — each reproduced against the real pinned SDK before fixing. A second review round fixed two more: a stale `partial` after a second catch-up failure (the coverage failure now clears only when a later anchored verification commits exactly the failed segment, publishing the healed snapshot without a timer) and a saturation marker that clipped away behind the numbers at narrow widths (`limited*` now precedes every number it qualifies, in the token field, the standalone cost field, both surfaces, both languages and ASCII), verified by unconditional narrow-width assertions. The B2b items listed as open at the time of this phase (long-history measurements, steady-state incremental cost, the 8-pair A/B, and real-host acceptance including resume, compaction, tree navigation, two footer extensions and streaming) were executed in the B2b round above; the defaults (`widget`, `observed`) were not changed and no default-footer switch was made.

## Unreleased — optional footer surface (phase 3)

**Opt-in, not the default.** `surface: widget | footer` (default `widget`) plus `/hud surface widget|footer` select where the HUD is drawn. `footer` replaces Pi's built-in footer through the official `ctx.ui.setFooter` slot and mounts no widget, removing the duplicate model/context/cost display; `placement` only affects the widget.

- **Footer lifecycle and ownership.** `/hud off` restores the built-in footer while the HUD owns the slot; surface switching, reload, shutdown and session replacement release the view, the branch subscription and timers and isolate old callbacks. If another extension replaced the HUD footer, the HUD never clears that footer on `off`/dispose and never takes it back on a refresh — only an explicit `/hud surface footer` re-claims it. A host without `ui.setFooter` falls back to the widget and records the reason for `/hud status`. Non-TUI modes perform zero terminal UI operations, and `scripts/check.mjs` allows `setFooter` only inside the marked boundary section of `src/footer.ts`.
- **Cached identity.** Display cwd (home abbreviated to `~`), model, provider, thinking level, session title and host Git branch. The title is read once at session start and on `session_info_changed`, never in render; the branch uses `footerData.getGitBranch()`/`onBranchChange()` and starts no Git process. The `*` dirty marker still requires the separate `git.enabled` probe.
- **Split usage.** Input, output, cacheRead and cacheWrite are counted and displayed separately (`obs* ↑in ↓out RcacheRead WcacheWrite`), so cached tokens are no longer added to fresh input. `CH` is the most recent valid assistant's `cacheRead / (input + cacheRead + cacheWrite)`, shown as `?` when the denominator is zero or the provider reported no cache data; reset, model switch and compaction clear a stale observation, and aborted/errored responses never replace the last valid one. Context remains the labelled `ctx(last)` snapshot.
- **Bounded extension statuses.** `footerData.getExtensionStatuses()` is shown in a separate area capped at 8 entries, 64 sanitized characters each and 2 rows (6 footer rows total), folding into an explicit `+N` marker without parsing strings into fake progress. Additions, changes and deletions made by another extension's in-place `setStatus` are detected inside the footer's own render pass — no polling, no host patch, no HUD event required.
- **Layout.** The widget keeps its fixed 1/2/3 rows; the footer body uses 2/3/4 rows for `minimal`/`balanced`/`full`, and tool start, completion, failure or settling never changes that count. Existing palettes, `color: false`, ASCII mode, bilingual labels and theme switching are unchanged.
- **Coverage difference is documented, not hidden.** By default (`usageScope: observed`) this surface does not read `getEntries()`/`getBranch()`/`getContextUsage()`, does not rebuild history and does not guess auto-compaction, subscription or provider-count flags, so the built-in footer's full-session totals are not reproduced; with the explicit `session` opt-in the dedicated ledger supplies them within the limits above. `/hud status` prints the difference.

Verification for this phase: 197 tests, `npm run verify`, `npm run package:check`, an 8-pair same-machine A/B against `af3a5e4` (re-run on the committed tree: widget render mean with usage +0.65 µs, 8/8 pairs; cached path unchanged to slightly cheaper; hooks within noise; footer scenarios new at 14.3 µs full / 0.104 µs cached with 12 statuses against a new 5 µs cached-footer gate; no existing gate relaxed), the pinned Pi 0.85.1 SDK contract check (now covering the footer data/factory/session-name contracts), the real RPC smoke, and the real PTY smoke with footer on/off, native-footer restoration and an independent extension status update. Real dark/light footer visual acceptance, a live-stream A/B, real-session usage parity and a two-extension ownership run in a real host remain pending.

## Unreleased — bounded activity information (phase 2)

Added a bounded per-tool-name category ledger: success (`✓`), failure (`!`) and interruption (`~`) are counted separately, a tool start is never a completion, duplicate completion events stay deduplicated. At most 16 tool names are retained and every further name is merged into a separate overflow record, so the ledger cannot grow with the number of distinct tools and a real tool literally named `other` keeps its own counters; the renderer shows the three most active categories plus a `+N` fold marker, and the overflow record is the only category that is localized. The activity row now prioritizes the running tool and any safe file target (basename of `read`/`write`/`edit`/`ls` only), then the error alert, then the categories, so narrow terminals fold activity detail instead of the context percentage, the current tool or an error.

Removed the empty `no bridged activity` placeholder: bridge agents/tasks appear only with valid bridge data, and the fixed row otherwise retains available usage information (or stays blank). Zero-compaction and zero-usage fields are no longer drawn. The widget keeps its fixed minimal/balanced/full 1/2/3 rows across tool start, completion, failure, settlement and idle transitions, and pastel/theme/mono, `color: false`, ASCII, English/Chinese labels and theme switching are unchanged. No pi-goal or todo-specific adapter was added.

Also added a width fast path: `visibleWidth`/`clip` now sum code points directly and fall back to `Intl.Segmenter` only for real grapheme-cluster candidates (marks, ZWJ, variation selectors, emoji, regional indicators). A seeded differential fuzz test asserts equivalence with the segmenter-based reference. The new activity fields therefore cost less than the old `tools*` line.

Verification for this phase: 149 tests, `npm run verify`, `npm run package:check`, and an 8-pair same-machine A/B against the pre-change commit (category-saturated uncached render p50 24.2→7.4 µs, mean 34.3→9.2 µs, p99 677→68 µs; concurrent activity mean 26.7→6.5 µs; empty idle row 20.6→2.8 µs; tool-pair hook p99 +0.24 µs; cached mean unchanged within noise; gates unchanged). The pinned Pi 0.85.1 SDK contract check, the real RPC smoke and the real PTY smoke passed; the PTY smoke now loads the bridge demo and verifies the full-preset summary row through a resize. Real-terminal visual acceptance, a live tool-stream A/B and the real rendering of native tool categories remain pending.

## Unreleased — per-field colors and semantic segments (phase 1)

Replaced the per-row `tone` with a bounded list of semantic segments (`{ role, text }`). Plain text is laid out and truncated to the terminal's visible width first; each surviving segment is colored afterwards, so a color can never change the layout. Row fields are capped at 12 and segments at 32, and lower-priority fields are dropped before overflow.

Added `palette: pastel | theme | mono` (default `pastel`) plus the in-memory `/hud palette` command. `pastel` gives model, thinking, path, branch, phase, context, body, label and separator their own candidates, with deeper same-family variants when the host theme indicates a light background; `theme` maps each role to a host theme token; `mono` and `color: false` stay plain. Alerts recolor only their own field: a high context value, a failed-tool count, interrupted work, bridge errors and `limited*` no longer tint a whole row, and zero counts stay neutral. `color: false`, ASCII mode, English/Chinese labels and the fixed 1/2/3-row widget layouts are unchanged.

Updated the final-line cache to clear its memoized styler on `invalidate()`, so a theme light/dark switch is re-detected while an unchanged width/state/theme still returns the identical array. Narrow identity rows reserve the measured context field (label, percentage and any warning) before spending width on the model, and rank the context meter above the model name below 45 columns; a long model name is clipped instead of pushing a high-usage warning out of the row. Synced configuration validation, `docs/config.schema.json`, the example config, a renderer-generated `docs/preview.txt` (now asserted by `npm run check`), and the bilingual README/CONFIGURATION/ARCHITECTURE/VERIFICATION/PERFORMANCE documents.

Verification for this phase: 126 tests, `npm run verify`, `npm run package:check`, an 8-pair same-machine A/B against the pre-change commit (uncached render mean −32.7%, p50 −40.6%, p95 −39.3%, cached mean −8.8%, uncached p99 +40.5% at 0.59 ms against the unchanged 5 ms gate), the pinned Pi 0.85.1 SDK contract check (now covering the theme-role tokens), the real RPC smoke and the real PTY smoke with live palette switching. Real dark/light terminal visual acceptance and live-stream A/B remain pending; footer takeover, quota data and historical usage totals were out of scope.

## 0.1.0 — 2026-09-19

Initial source delivery, inspired by Claude HUD and designed around Pi 0.85.1's native extension contract.

Added a passive named widget with fixed minimal/balanced/full layouts, English/Simplified Chinese labels, bounded tool tracking, honest last-response context snapshots, observed usage estimates, a versioned opt-in agent/task bridge, async capped config reads, an optional idle-only Git probe, and `/hud` commands. No runtime dependencies, token-stream listeners, history scans, model requests or prompt injection were added.

Added deterministic state/lifecycle/render/config/Git tests, local real-Git tests, synthetic performance budgets, offline package/import smoke checks, source research, bilingual READMEs, CI/release workflows, and explicit pinned-SDK/RPC/PTY checks for a network-enabled runner.

Known verification gap at delivery: the actual Pi SDK, real Pi RPC/TUI smoke and live-stream terminal A/B could not be executed in the offline sandbox. Cross-platform GitHub CI and draft release are prepared, not remotely executed. See [verification](docs/VERIFICATION.md). The performance objective is bounded, imperceptible marginal overhead; this is not an unconditional zero-overhead certification.
