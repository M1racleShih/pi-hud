## Unreleased — `spd*` generation-speed field (A-refined algorithm)

Adds the `spd*` (en) / `速度*` (zh-CN) field: the average generation speed of the last completed assistant message. The algorithm is the documented "A refined" choice from the ecosystem survey (pi-token-speed, pi-tps, pi-pulse, …): numerator is the provider-reported exact `usage.output`; denominator is the wall-clock window from the message's first content-bearing streaming delta to `message_end` — so prefill/TTFT wait and tool execution are excluded by construction, with no chars-per-token estimation anywhere. There is deliberately no live rate while streaming (no sliding window, smoothing or spinner): the value updates once per assistant message. Five discard guards keep a bad sample from overwriting the previous valid value (error/abort, missing usage, unobserved first token, sub-50 ms window, model mismatch); reset and a model switch clear it, compaction keeps it. The single high-frequency acquisition path is a pinned, auditable bridge: `message_start` (low frequency, joins `OBSERVED_EVENTS`) arms it, `message_update` records exactly one timestamp and then fuses behind a marked `stream-boundary` in `src/state.ts` (O(1) per delta, no string retention, no repaint from fused deltas, zero timers); `scripts/check.mjs` pins `STREAM_EVENTS == ["message_update"]` and the fused early-return. Field renders on the widget `full` row and the footer usage row at drop priority 28 (folds before the usage counters), hidden by `showSpeed: false` (measurement always runs). Full spec: `docs/TOKEN-SPEED.zh-CN.md`. Package description updated ("no token-stream listeners" no longer held); schema/example/config docs, both READMEs, ARCHITECTURE and the generated preview updated in sync; 260 tests green.

## Unreleased — optional full-session usage ledger (phase 3 B2a)

**Opt-in, not the default.** `usageScope: observed | session` (default `observed`) plus `/hud scope observed|session` select which numbers the usage fields show. The scope is independent of `surface`, which stays `widget` by default. `session` displays full-session totals labelled `sess*` (Chinese `全会话*`); the observed counters, `ctx(last)`, `CH` and tool categories keep their since-attach/reset scope in both modes.

- **Ledger, not counters.** A dedicated module (`src/usage.ts`) aggregates the current SessionManager's entries — all branches, pre-compaction messages, error/aborted responses and summary records — under the built-in footer's four record categories: assistant, tool results carrying usage, compaction and branch summaries. The four token fields and `cost.total` stay separate; cached tokens are never folded into input.
- **Bounded acquisition.** One sliced, cancelable baseline per rebuild (512 entries or ~2 ms per slice, whichever comes first) captured with one `getEntries()` call; steady turns reconcile only newly committed records at `turn_end`/`agent_settled` by walking `getEntry(id).parentId` from the leaf back to the committed cursor, so increments and baselines never overlap and duplicate notifications never double count. Tree navigation and compaction rebuild once; a session switch, `/hud off` or leaving `session` cancels all work and releases the O(N) array. Chain anomalies drop the whole uncommitted batch, mark the data partial and schedule exactly one recovery rebuild — never an idle retry loop. `message_end` only marks the snapshot updating, so a later extension replacing the observed message cannot skew the account.
- **Honest missing data.** Missing, negative, NaN or Infinity values mark that field unknown (`+?`) instead of being dropped; an assistant without usage marks the data incomplete; a usage-less tool result is out of scope, never an unknown charge; a usage-less summary keeps the token subtotals and marks the cost incomplete; an explicit zero cost stays a valid zero; all-unknown cost shows `?`; saturated sums show `limited*`. `↻` (ASCII `~`) marks updating, `?` marks loading, and the scope label plus markers sit before the counters so right-edge truncation cannot hide them. A host without the read-only entry surface degrades explicitly to observed-labelled data; `/hud status` reports scope, status, rebuild reasons, host call counts and missing-field counts.
- **Audited boundary.** `getEntries`/`getEntry`/`getLeafId`/`getSessionId` may be called only inside the marked history boundary of `src/usage.ts`, never in render or per-token paths; `getBranch`/`getContextUsage` stay forbidden everywhere. `scripts/check.mjs` enforces this like the footer boundary.

Verification for this phase: 244 tests (`tests/usage.test.mjs` covers the B1 correctness matrix with an independent oracle reducer), `npm run verify` with unchanged gates, `npm run package:check`, the pinned Pi 0.85.1 SDK contract check (now covering the ledger manager/entry/`turn_end` contracts) and a new `scripts/usage-oracle-check.mjs` that runs the ledger against real `SessionManager.inMemory` histories and compares totals with the SDK's own usage-totals module. An external review round fixed three reported issues — a frozen ledger after `resetLeaf()`-style tree navigation to the root (the null cursor is now a legal anchor), a missing recovery rebuild after a failed baseline catch-up (over-cap append bursts now recover), and session cost fields that lost their scope/status marks when rendered without the token field (`sess*`, updating, incompleteness and saturation marks are now carried independently) — each reproduced against the real pinned SDK before fixing. A second review round fixed two more: a stale `partial` after a second catch-up failure (the coverage failure now clears only when a later anchored verification commits exactly the failed segment, publishing the healed snapshot without a timer) and a saturation marker that clipped away behind the numbers at narrow widths (`limited*` now precedes every number it qualifies, in the token field, the standalone cost field, both surfaces, both languages and ASCII), verified by unconditional narrow-width assertions. The B2b items listed as open at the time of this phase (long-history measurements, steady-state incremental cost, the 8-pair A/B, and real-host acceptance including resume, compaction, tree navigation, two footer extensions and streaming) were executed in the B2b round above; the defaults (`widget`, `observed`) were not changed and no default-footer switch was made.

## Unreleased — optional footer surface (phase 3)

**Opt-in, not the default.** `surface: widget | footer` (default `widget`) plus `/hud surface widget|footer` select where the HUD is drawn. `footer` replaces Pi's built-in footer through the official `ctx.ui.setFooter` slot and mounts no widget, removing the duplicate model/context/cost display; `placement` only affects the widget.

- **Footer lifecycle and ownership.** `/hud off` restores the built-in footer while the HUD owns the slot; surface switching, reload, shutdown and session replacement release the view, the branch subscription and timers and isolate old callbacks. If another extension replaced the HUD footer, the HUD never clears that footer on `off`/dispose and never takes it back on a refresh — only an explicit `/hud surface footer` re-claims it. A host without `ui.setFooter` falls back to the widget and records the reason for `/hud status`. Non-TUI modes perform zero terminal UI operations, and `scripts/check.mjs` allows `setFooter` only inside the marked boundary section of `src/footer.ts`.
- **Cached identity.** Display cwd (home abbreviated to `~`), model, provider, thinking level, session title and host Git branch. The title is read once at session start and on `session_info_changed`, never in render; the branch uses `footerData.getGitBranch()`/`onBranchChange()` and starts no Git process. The `*` dirty marker still requires the separate `git.enabled` probe.
- **Split usage.** Input, output, cacheRead and cacheWrite are counted and displayed separately (`obs* ↑in ↓out RcacheRead WcacheWrite`), so cached tokens are no longer added to fresh input. `CH` is the most recent valid assistant's `cacheRead / (input + cacheRead + cacheWrite)`, shown as `?` when the denominator is zero or the provider reported no cache data; reset, model switch and compaction clear a stale observation, and aborted/errored responses never replace the last valid one. Context remains the labelled `ctx(last)` snapshot.
- **Bounded extension statuses.** `footerData.getExtensionStatuses()` is shown in a separate area capped at 8 entries, 64 sanitized characters each and 2 rows (6 footer rows total), folding into an explicit `+N` marker without parsing strings into fake progress. Additions, changes and deletions made by another extension's in-place `setStatus` are detected inside the footer's own render pass — no polling, no host patch, no HUD event required.
- **Layout.** The widget keeps its fixed 1/2/3 rows; the footer body uses 2/3/4 rows for `minimal`/`balanced`/`full`, and tool start, completion, failure or settling never changes that count. Existing palettes, `color: false`, ASCII mode, bilingual labels and theme switching are unchanged.
- **Coverage difference is documented, not hidden.** By default (`usageScope: observed`) this surface does not read `getEntries()`/`getBranch()`/`getContextUsage()`, does not rebuild history and does not guess auto-compaction, subscription or provider-count flags, so the built-in footer's full-session totals are not reproduced; with the explicit `session` opt-in the dedicated ledger supplies them within the limits above. `/hud status` prints the difference.

Verification for this phase: 197 tests, `npm run verify`, `npm run package:check`, an 8-pair same-machine A/B against `af3a5e4` (re-run on the committed tree: widget render mean with usage +0.65 µs, 8/8 pairs; cached path unchanged to slightly cheaper; hooks within noise; footer scenarios new at 14.3 µs full / 0.104 µs cached with 12 statuses against a new 5 µs cached-footer gate; no existing gate relaxed), the pinned Pi 0.85.1 SDK contract check (now covering the footer data/factory/session-name contracts), the real RPC smoke, and the real PTY smoke with footer on/off, native-footer restoration and an independent extension status update. Real dark/light footer visual acceptance, a live-stream A/B, real-session usage parity and a two-extension ownership run in a real host remain pending.
